# Принятые решения и отличия от ТЗ

Всё ниже можно поменять — это осознанные упрощения под «минимализм MVP» и ответы из раздела 13 ТЗ.

## Объём
- Реализованы все этапы M0–M5. Календарь — **только недельный** (по вашему ответу).
- Без: повторяющихся событий (поля `rrule` в БД заведены, UI нет), вложений, Google Calendar, ручной сортировки (поле `position` есть), дедлайнов.

## Технические отличия
| Что в ТЗ | Что сделано | Почему |
|---|---|---|
| Drizzle / Prisma | «Голый» `better-sqlite3` + SQL-миграции по `PRAGMA user_version` | FTS5 всё равно требует сырого SQL; на 2 зависимости и один слой абстракции меньше |
| Отдельные ресурсы `checklist-items`, `reminders` | Чек-лист и напоминания — часть задачи/события (`checklist: []`, `reminders: [минуты]`) | Один запрос вместо нескольких, нет рассинхрона; серверу всё равно нужно пересчитывать напоминания при смене срока |
| Внешние ключи в БД | Нет FK-ограничений, есть индексы; изоляция — фильтр `user_id` в каждом запросе | Мягкое удаление и «чужие id → 404» проще без каскадов; миграция на Postgres не усложняется |
| `POST /tasks/:id/snooze` | Не сделан отдельный эндпоинт; откладывание — кнопки в чате, а из приложения — смена срока/напоминаний | Другого места вызова в интерфейсе нет |
| Свой `user_id` | `user_id` = Telegram ID | Один пользователь = один Telegram-аккаунт |
| Lint в CI | В CI: typecheck, тесты, сборка | Минимум конфигурации; строгий TypeScript ловит основное |

## Поведение (мои допущения — проверьте)
- **Настойчивые повторы включены по умолчанию** (30 мин, 3 повтора); выключаются в настройках или на задаче.
- **Выполненные задачи** остаются в блоке «Выполненные» до вечерней сводки, затем скрываются из списка, но находятся поиском. Если вечерняя сводка выключена — до полуночи.
- **Автонапоминание** «в момент срока» ставится для задач с временем; для задач только с датой — не ставится (о них напомнят сводки), но можно добавить вручную («В день срока» — в 09:00 по умолчанию).
- **«Просрочено»** — задачи с датой раньше сегодняшней; сегодняшняя задача с прошедшим временем остаётся в «Сегодня».
- **Часовой пояс** берётся из устройства при первом входе (запасной — `DEFAULT_TZ`). Время задач/событий хранится в UTC и показывается в поясе из настроек. При смене пояса напоминания для дел «только с датой» пересчитываются.
- Тихие часы подавляют **сводки и повторы**, но не одиночные напоминания (как в ТЗ).
- Неотправленное из-за ошибки Telegram (429/сеть) не теряется: попытка повторяется. После блокировки бота (403) рассылка пользователю прекращается до его следующего сообщения боту.
- Входящие: правка сообщения в Telegram обновляет запись, пока она не разобрана; альбом склеивается в одну запись; разобранные записи удаляются через 30 дней.
- Цвета категорий хранятся один раз; в тёмной теме приложение автоматически их осветляет.

## Что нужно проверить вам
Работу в самом Telegram (см. чек-лист в README): у меня не было доступа к Telegram, поэтому проверены автотестами сервер, планировщик, сводки и проверка подписи, а также сборка клиента, но не внешний вид на устройствах. Особенно посмотрите: свайпы на iOS, поведение клавиатуры в шторках, нативные кнопки «Сохранить»/«Назад» и тёмную тему.
